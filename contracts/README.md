F-730 also exposed why it survived: a full seed is not re-runnable — the foundation and ledger mint
fixed ids from a fixed stream and collide with themselves — so adding 4,000 rows meant destroying the
volumes and regenerating 20,000 journal lines first. `pnpm db:seed -- --only subledger` now resumes a
single stage, which is what makes the next phase's seed data cheap enough to actually add.

Two SQL type defects travelled with them, both from the same habit of trusting a cast to arrive late.
`journals.journal_type` is `text` with a CHECK, not an enum, so `$7::journal_type` failed at plan
time for every document that had to open its own journal. And `coalesce($11, 0)::numeric` infers the
parameter as **integer** from the literal `0` and casts the result afterwards — so an ordinary
`'5.00'` unit price failed to parse before the cast was ever reached. The cast belongs inside:

## Rules

1. **`project plan/` is never modified.** It is the immutable v1.0 handoff. Where this directory
   disagrees with it, this directory wins and the audit finding explains why.
2. **Event types are immutable once published.** A breaking payload change is a new `event_version`.
   The `forbidden:` block in `events.yaml` records every superseded name so a developer grepping the
   old prose lands on the canonical form.
3. **The permission registry is generated** from `openapi.yaml` `x-permission` values. CI fails if a
   route declares a permission absent from the registry, or a role references one that does not
   exist. This is what makes Gate B's "authorization tests cover every mutation route" provable.
4. **Migrations are forward-only.** Rollback is a new forward migration (ADR-0008).
5. **Anything Gate C, D, E or G tests is raw SQL, not Prisma** (ADR-0008 §2).
